# RiceScan Stitcher

## 水稻苗床扫描视频智能拼接系统

RiceScan Stitcher 是一款 PySide6 + OpenCV 桌面软件，用于把相机在近似平面场景上方平移扫描拍摄的视频转换为一张全景母图。它主要服务后续秧盘标注和水稻吐水表型分析，也可用于具有相似运动方式的其他扫描视频。

当前主流程不是旧版 README 所描述的“裁边后直接 `np.concatenate`”，而是：

```text
视频预分析 → 两阶段关键帧抽取 → 特征匹配与几何校验
→ 时间跨度路径和桥接恢复 → 位姿图全局坐标 → 曝光补偿
→ 条带/通用所有权合成 → 有效区域裁剪 → 质量评分与自动重试
```

软件的设计目标是：**优先保证几何稳定、扫描范围完整和结果可诊断，而不是盲目追求像素级完全对齐。**

---

## 1. 能做什么

- 读取 MP4，显示时长、分辨率、帧率、总帧数、文件大小、编码、宽高比和估算码率等信息。
- 在拼接前单独分析运动方向、扫描跨度、模糊比例、推荐关键帧数和拼接难度。
- 根据空间覆盖而不是单纯根据视频时长推荐关键帧数量，也允许使用固定数量。
- 使用清晰度、亮度、时间均匀性和补帧机制建立关键帧集合。
- 使用网格均匀特征、RANSAC、多模型几何估计和严格变换校验完成配准。
- 通过时间跨度路径、桥接恢复和中间参考帧位姿图减少中段截断及链式漂移。
- 默认使用沿主运动轴划分的 SafeStrip 条带合成；二维自由运动时回退到通用像素所有权合成。
- 对结果进行时间覆盖、内部断带、帧贡献、边缘密度、剪切比例等质量检查。
- 质量不足时依次尝试默认、加密帧、严格几何三种策略，并保留最佳结果。
- 支持单视频和文件夹批量处理，输出 PNG、JPEG 或 TIFF。
- 保存逐帧、逐变换和逐阶段报告，便于解释“某一帧为什么被保留或拒绝”。

## 2. 不适用或需要谨慎的情况

- 相机原地旋转拍摄的一般全景照片；
- 明显非平面、强视差、频繁变向或自由二维路径复杂的视频；
- 大面积重复纹理且缺乏苗盘边缘、地面等结构特征的视频；
- 长期失焦、严重运动模糊或相邻帧几乎不重叠的视频；
- 需要测量级几何精度或辐射定量的场景。

软件可以输出单帧保底图，但保底图不是全景拼接成功。它会以 `_FALLBACK` 文件名和 `SINGLE_FRAME_FALLBACK` 状态明确标记。

## 3. 安装与启动

### 3.1 环境

- 建议 Windows 10/11；
- 建议 Python 3.12；
- 依赖见 `requirements.txt`：PySide6、OpenCV、NumPy、Pillow。

### 3.2 命令行安装

在本目录执行：

```bat
py -3.12 -m venv .venv
.venv\Scripts\activate.bat
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python main.py
```

### 3.3 双击启动

- `启动软件.cmd`：优先调用本目录 `.venv\Scripts\pythonw.exe`，否则查找系统 `PATH` 中的 `pythonw`；启动失败时写出并打开 `launcher_error.log`。
- `启动软件_调试.cmd`：使用带控制台的 `python.exe`，便于查看算法日志和退出代码。
- `启动软件.ps1`：PowerShell 启动方式，同样优先使用项目 `.venv`。

不依赖任何特定 Conda 环境名称或个人用户目录。

## 4. 单视频快速上手

1. 在“单视频处理”页点击“浏览...”，选择一个 MP4。
2. 建议先点击“分析视频”，查看运动方向、扫描跨度和推荐帧数。
3. 保持“自动推荐”开启；若已明确需要固定帧数，再关闭自动推荐并设置“目标关键帧”。
4. 选择输出画质。首次处理建议使用“自然”。
5. 点击“1. 抽取帧”可单独检查抽帧缩略图；这一步不是拼接前的强制步骤。
6. 点击“2. 预览拼接”。该按钮会从原视频重新执行完整分析和拼接，**不会直接拿上一步的缩略帧列表来拼接**。
7. 在右侧滚轮缩放、拖拽平移，使用“重置视图”或“查看原始帧”进行对比。
8. 点击“3. 保存拼接图”。保存也会重新运行完整流水线，而不是仅把预览缓存写盘，因此运行时间和报告可能与预览不同。

### 为什么“抽取帧”和“预览拼接”的数量可能不同

- “抽取帧”是独立预览：使用当前“目标关键帧”数值进行两阶段抽取；自动推荐复选框不会在这一次单独抽取中触发视频预分析。
- “预览拼接”是完整流水线：自动推荐开启时，会重新分析视频并实测匹配可行性，然后再抽取和筛选。
- 拼接还会经过匹配图、桥接、全局几何校验和实际像素贡献检查，所以“选中”“有效”“参与”“贡献”本来就是不同口径。

## 6. 批量处理界面：每个组件和选项

批量模式只扫描输入文件夹顶层的 `*.mp4`，不递归子文件夹。每个视频独立调用与单体相同的 `SmartStitcher.process_video()`，单个视频失败不会终止整批。

| 组件 / 选项 | 工作方式 |
|---|---|
| 输入文件夹 | 必填。没有 MP4 时会提示，不会创建空任务。 |
| 输出文件夹 | 必填。每个视频建立一个以视频 stem 命名的子目录。 |
| 关键帧模式：自动推荐 | 默认。逐视频计算空间覆盖、重叠和匹配可行性。 |
| 关键帧模式：固定数量 | 所有视频使用同一个目标帧数。 |
| 固定值 | 默认 12，范围 2～30；仅固定数量模式可编辑。 |
| 输出画质 | 与单视频相同：自然、标准、增强。 |
| 输出格式 | PNG、JPEG、TIFF。PNG 使用无损压缩；JPEG 可设置质量；TIFF 写出 `.tif`。 |
| JPEG 质量 | 默认 95，范围 80～100；只有选择 JPEG 时启用，对 PNG/TIFF 无效。数值越高通常质量越高、文件越大。 |
| 开始批量处理 | 后台依次处理所有视频，更新日志、进度和单文件结果。 |
| 仅分析不拼接 | 只逐个输出预分析结果，不生成全景图；仍需输入文件夹，但不要求输出文件夹。 |
| 停止 | 设置取消标志，在当前视频结束后停止继续取新视频；不能强制中断正在运行的单个视频。 |
| 处理日志 | 显示每个视频的推荐、选中、有效、贡献、质量分、尝试次数、输出路径或错误。 |
| 汇总 | 显示成功和失败数量，并给出 `batch_report.csv` 位置。 |

### 批量输出结构

```text
<输出文件夹>/
├── batch_report.csv
├── batch_report.json
└── <视频名>/
    ├── stitched.png                 # 或 stitched.jpg / stitched.tif
    ├── stitched_FALLBACK.png        # 仅单帧保底时采用此类名称
    ├── report.json
```

## 7. 核心算法如何工作

### 7.1 AUTO 视频预分析

`VideoAnalyzer` 均匀读取约 12～60 个分析帧，缩小为半分辨率灰度图，使用 `phaseCorrelate` 估计相邻分析帧位移，再换算回原图像素。

- 主运动轴：累计 X/Y 位移绝对值较大的方向；
- 扫描跨度：主轴位移中位数 ÷ 分析帧间距 × 总帧数；
- 目标重叠率：默认 60%；
- 推荐公式：`round(span / ((1 - 0.60) × 主轴帧尺寸)) + 1`；
- 推荐范围：默认限制在 4～20 帧；几乎无运动时取 3 帧。

随后 `_verify_auto_keyframes()` 按推荐间距读取最多 4 个探针帧，实测相邻相似变换或仿射匹配。如果匹配失败，每轮增加 4 帧，直到可匹配或达到上限。

难度等级由平均相位相关响应、模糊比例和方向一致性共同决定：

- `BAD`：响应 < 0.05 或模糊比例 > 50%；
- `DIFFICULT`：响应 < 0.15、模糊比例 > 25% 或方向一致性 < 70%；
- `GOOD`：响应 ≥ 0.30、模糊比例 ≤ 10% 且方向一致性 ≥ 90%；
- 其余为 `NORMAL`。

### 7.2 两阶段关键帧选择

**阶段 A：候选池**

- 均匀采样 `min(总帧数, max(36, 3 × 目标帧数))` 帧；
- 在最长边不超过 480 的分析图上计算 Laplacian 方差和平均亮度；
- 默认拒绝清晰度 < 100、亮度 < 30 或 > 225 的帧；
- 当前主选择器不执行重复帧 SSIM 过滤或最小运动过滤，报告中会如实写明 `none`。

**阶段 B：时间均匀精选与补帧**

- 候选多于目标时，在候选列表中按时间顺序均匀取目标数量；
- 候选不足时先全部保留，再从初始采样点之外按 60% 清晰度阈值补帧；
- 补帧按清晰度优先选取，最后重新按时间排序；
- 每个保留/拒绝决定都可记录到 `frame_selection_report.json`。

若有效拼接帧数与目标严重不符，主流水线还会执行两级恢复：清晰度阈值依次降为原来的 60% 和 40%，目标提高到 `max_keyframes`；仍不足时再尝试时间均匀清晰帧采样。

### 7.3 特征匹配和变换模型

默认使用 ORB，但高级配置也支持 SIFT、AKAZE。

1. 在 8×8 网格中限制每格最多 40 个强特征，减少植物中心重复纹理垄断匹配。
2. KNN + Lowe ratio test，默认比率 0.75。
3. 默认至少 12 个良好匹配、8 个 RANSAC 内点、内点率 ≥ 0.20。
4. 同一组匹配点分别估计 Similarity、Affine、Homography。
5. 对每个候选执行尺度、纵横比、旋转、投影面积、透视分量、行列式、条件数、角点位移和四边形自交校验。
6. 简单模型按“内点率 × 100 − 重投影误差 − 几何畸变惩罚”评分。
7. Homography 只有在内点率至少高 0.05 且重投影误差不超过简单模型 70% 时才优先采用。
8. 所有特征模型失败时，最后尝试相位相关纯平移；响应低于 0.05 时拒绝。

### 7.4 时间覆盖、位姿图与桥接

- 关键帧先与后续最多 3 帧建匹配边。
- `select_span_path()` 选择首尾时间跨度最长的有效路径，而不是简单保留最大连通块。
- 桥接恢复从路径尾部、头部沿时间轴扩展；直接连接失败时插入 2 或 4 个中间帧逐环验证，目标是至少覆盖约 80% 时间范围。
- 正式位姿图再次估计 i+1/i+2/i+3 边，并删除相对中位运动明显异常的边。
- 以中间帧为单位矩阵参考，通过 BFS 选择跳数最少的路径；跳数相同时优先高内点率。
- 不可达或全局几何不合理的帧被剔除，不强行写入单位矩阵冒充有效拼接。

### 7.5 曝光、 warp 与合成

- 曝光补偿按相邻整帧平均灰度估计增益，每步限制在 0.95～1.05，再对累计增益做几何均值归一化，降低长链曝光漂移。
- 图像使用 `INTER_LINEAR` warp；有效掩膜使用 `INTER_NEAREST` 并重新二值化。
- 默认 `SafeStripComposer` 对帧中心做 PCA，主方向方差占比 ≥ 0.90 时按主轴排序并划分连续条带。
- 每个有效像素分配给轴向距离最近且确有内容的帧；接缝在相邻中心间 30%～70% 的位置候选中选择灰度差较小者。
- 接缝两侧默认仅 8 像素窄带交叉淡化，并且只在两帧都有效的像素上执行。
- 主轴方差占比 < 0.90 时回退到通用质量所有权合成：综合局部清晰度、曝光、中心距离、匹配置信度、边缘距离、重投影误差等，再做局部多数投票和窄带融合。
- 最终从有效所有权掩膜的最大连通区域中求最大内接轴对齐矩形，去除外侧无效区域。

### 7.6 质量评分和自动重试

每次尝试从 100 分开始，主要扣分如下：

| 情况 | 扣分或限制 |
|---|---|
| 正常多帧 / 帧数偏少 / 仅 2 帧 / 单帧保底 | 0 / 10 / 35 / 60 分 |
| 实际贡献帧少于 3 | 再扣 15 分 |
| 多帧贡献验证警告 | 每项扣 8 分，最多 24 分 |
| 视野未展开 | 扣 20 分 |
| 最终/原图边缘密度比 > 1.3 或 > 1.5 | 扣 5 或 15 分 |
| 黑白剪切像素合计 > 1% | 扣 10 分 |
| 时间覆盖 < 0.6、出现断带或明确部分失败 | 总分上限 40 |
| 时间覆盖在 0.6～0.8 之间 | 扣 15 分 |

尝试顺序：

1. `default`：当前配置；
2. `densify`：关闭自动推荐，在推荐/固定目标基础上增加 6 帧，受自动上限约束；
3. `strict`：旋转上限乘 0.7，缩放收紧为 0.85～1.20，透视上限减半。

达到 80 分即停止；否则从所有尝试中选择最高分，而不是盲目使用最后一次。仍只能得到单帧时，结果会明确标记保底。

## 11. 常见问题

### 拼接只有两帧或单帧

查看 `frame_selection_report.json` 和 `transform_report.json`：分别确认帧是在质量过滤、匹配图、全局几何校验还是贡献检查阶段减少。优先改善清晰度、重叠和结构特征，再考虑使用固定更多帧或调整几何阈值。

### 拼接只覆盖中段

查看 `completeness.time_coverage_ratio`、`steps.bridge` 和 `15_continuity/`。桥接失败通常意味着首尾帧无法建立满足几何约束的连接。

### 结果扭曲或比例异常

不要首先放宽 Homography 限制。先检查变换报告中的尺度、旋转、透视强度和条件数，可尝试让自动重试进入 `strict`，或在高级配置中进一步限制模型。

### 内存占用高

主流水线会同时保留多个原分辨率帧、warp 后画布和掩膜；全景画布越大，内存越高。关闭磁盘调试只能减少 I/O，不能消除内存中的画布。应缩小输入分辨率或分段处理。

### 输出和预览不完全一致

保存按钮会重新运行完整流程，且保存与预览的调试/质量指标上下文可能不同。需要严格复现时，应直接调用 `SmartStitcher.process_video()` 一次并同时保存返回图像和报告，而不是分别点击预览和保存。
